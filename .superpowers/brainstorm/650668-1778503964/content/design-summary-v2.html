AI 私人电台 DJ · Agent 架构 · 深色 Matrix 主题

一、Agent 架构

Perception用户消息 + 环境上下文 + 偏好历史
Routing显式命令直执行 / 自然语言转 Reasoning
ReasoningPlan-and-Solve 三段式 + ReAct 交替循环

FeedbackDJ 口吻 + 更新播放列表 + WS 推送状态快照

二、关键工程风险 & 应对（原型阶段最高优先级）

⚠️ 1. WebSocket 状态同步

前端 + Agent + 外部 API 三端状态，断线重连后如何恢复？

方案：Agent 通过 WS 推送不可变的状态快照（snapshot），不是零散 delta。前端只负责渲染快照，不维护派生状态。重连后服务端重推最新快照。

协议：{type:"state_snapshot", song, playlist, agent_log, timestamp, seq}

⚠️ 2. Agent 推理时延 vs 前端体验

Plan+Solve+ReAct 可能数秒，界面不能僵死。

方案：Agent 进入 Reasoning 第一步，立刻通过 WS 推一条日志——"Malio 正在感受你的情绪…决定为你选一些明亮的调子"。前端收到立即显示，不等最终结果。把最长的时延变成 AI 思考秀。

⚠️ 3. Canvas 粒子绕流性能

256 粒子 × 碰撞检测，中低端手机可能掉帧。

方案：开发初期加 FPS 计数器。FPS 持续 < 30 → 自动熔断，停止绕流，改为简单透明度避让或粒子穿透。动画底线永远是流畅，不是效果炫。

⚠️ 4. 用户状态文件演进

taste.md / routines.md / mood-rules.md 初期用文件够用，后期何时切数据库？

方案：Phase 1-2 用 JSON/Markdown 文件，结构清晰易调试。访问频繁时切 SQLite + 版本控制，防止错误推理覆盖用户记忆。这个切换点留到 Phase 3。

四、DJ 人格（prompts/dj-persona.md）

不只是服从，而是有判断力。深夜点快歌时温和提示："也许一首舒缓的爵士会更适合夜晚？" —— 这是 AI DJ 和播放器的本质区别。
